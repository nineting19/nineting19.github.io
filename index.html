三类搜索结果，怎样分别留证据？

可以用拾玖搜证台手动整理少量豆包网页测试：保存完整回答、实际来源和人工核对结果，分别记录给网址读取、按名称发现、无品牌需求推荐。记录器当前免费，无需工具账号或 API Key。

给网址：网址读取

记录实际给定的地址、完整问句和回答。核对它是否读到页面的具体内容；通过不计入独立发现。

给名字：名称发现

不给网址，核对主体、至少两项问句未给出的事实和实际支持来源。纯名称与名称加功能分别编号。

只说需求：需求推荐

不给品牌、作者或网址。除正确事实与来源外，还要确认回答真的推荐了适用工具；只在来源面板出现不算推荐。

实际操作：提问在豆包，记录在这里

  1. 打开记录器，填写批次、问题原文与环境，手动选择“测试路径”。在豆包另开新对话正常提问；登录账号的记忆条件仍需单独记录。
  2. 粘贴完整回答和豆包实际给出的来源，自己打开链接核对。来源面板、正文提及、明确推荐分别判断；技术中断保留，不算未命中。
  3. 点击“保存这条证据”，记录写入当前浏览器的 localStorage。截图单独存在自己的文件夹，备注只写文件名；没有图片上传或附件打包。
  4. 点击“导出 JSON”备份，“导出 CSV”做表格分析，或“导出报告”取得 Markdown。交付时另附截图，并保持原题复测；工具不会自动核验事实。

分清你在验证什么

三种路径，分别核对。

读到了网页、按名字找到了、按需求推荐了，是三件不同的事。

01

名称发现

给出对象名称，让系统自行寻找来源。核对主体、具体事实和支持链接。

纯名称与“名称＋功能”还需按问题编号分开比较。

02

需求推荐

只描述需求，不给品牌、作者或网址。检查是否实际推荐了适用的对象。

它更接近真实用户还不知道产品名称时的提问。

03

网址读取

主动提供网址，检查页面能否读取、信息是否正确、引用是否支持结论。

这是读取诊断，单独统计。

使用方式

提问 → 核对 → 保存 → 备份

  1. 固定问题

    确定问题编号和批次，记录平台、日期、模式、登录与联网条件。

  2. 保留原始证据

    在平台正常提问，复制完整回答与当次来源；打开链接核对支持内容。

  3. 点击保存

    填写路径和复核标记，点击“保存这条证据”。记录留在当前浏览器。

  4. 导出再比较

    导出 JSON 备份、CSV 表格或 Markdown 报告。下一轮保持原题再测。

清除站点数据可能丢失记录。换浏览器或设备前请导出 JSON；没有自动同步，也没有未保存草稿的恢复承诺。
