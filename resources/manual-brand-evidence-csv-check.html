记录AI搜索对品牌的推荐结果：18列表格与本地CSV检查脚本

2026-11-16

少量检查AI搜索对品牌的推荐结果，用表格、完整回答和截图就能开始。先把问题及测试条件记全，再检查来源是否支持回答；如果要集中保存这些人工记录，可以使用我维护的免费工具拾玖搜证台。

本文给出一份18列空白CSV，以及只在本地读文件的Node.js检查脚本。它适合发现漏记、编号重复与标记矛盾；不能替你判断回答真假，也不自动问豆包。

先分清：保存对话和记录推荐结果有什么区别？

导出一段聊天，能帮助你保留回答。做品牌推荐检查，还需要知道：问的是品牌名，还是没有品牌的真实需求？回答只是提到名字，还是建议使用？它给的功能和入口是否正确？这次来源支持了哪一条具体说法？

这些判断要人工做。建议把一次实际问答记作一条记录，完整原文和截图单独保留。后来另搜到的网页不能补成当次引用；没有推荐、拒答和验证阻断也保留。

第一步：下载表格，先固定问题和条件

下载18列空白CSV。文件只有表头，没有示例成绩。它是人工底稿，不是拾玖记录器的JSON导入文件，也不是GEO医生的采样CSV。

表头按四组理解：

分组实际字段
本次条件记录编号、实际观察时间及时区、平台及入口、可见模式、账号条件、记忆状态及依据
问题与回答问题编号、路径、原始问句、回答状态、完整回答或文件名
推荐与证据是否提及目标、是否实际推荐目标、当次来源网址、来源支持核对、工具或官网入口检查
附件与备注截图文件名、备注

实际观察时间可以写成 2026-11-16T15:00:00+08:00，这是格式示例，不是一次真实采样。记发生时间，不用整理或保存文件的时间代替。无法回忆准确时间时，如实记未知，并在复核中单列。

路径分别填“名称发现”“需求推荐”“网址读取”。这三组分别统计。日常需求题不要带自己的品牌、作者、网址，也不要为获得某个产品的回答而拼接长功能清单。题目定好后保留原句。

每题新开对话，记录账号、入口、可见模式和实际记忆设置。新对话并不能排除同一账号的全部个性化；设置无法确认时写“未核实”，不要默认已经关闭。

第二步：先在平台正常提问，再手动记录

在豆包或其他平台正常取得回答后，手动保存完整原文。来源面板能打开时，记录当次实际显示的链接；没有显示就写“未显示来源”，不能凭模型语气判断它已经搜索。截图文件名填真实附件名，文件另外保存，CSV不会嵌入图片。

建议这样标记：

  • 回答状态：完成、拒答、登录阻断、验证阻断、技术失败、未发送。
  • 是否提及目标、是否实际推荐目标：是、否、未核实、不适用。
  • 来源支持核对：写具体核对结论，例如“该页面支持手动导出，但不支持回答中宣称的自动监控”。没有核对就明确写“未核实”。
  • 工具或官网入口检查：检查用户会点的实际入口，不只看来源标题。打不开、跳错主体也应保留。

“推荐了”与“说对了”是两件事。出现名字但功能有错，不应报告成准确推荐；遇到登录或验证没有取得回答，也不应直接计为未推荐。

第三步：用本地脚本找漏记和矛盾

下载 check-brand-evidence.cjs，与CSV放在一个文件夹。安装Node.js 18或更新版本后，在该文件夹运行：

node check-brand-evidence.cjs "我的记录.csv"

不需要安装第三方包。脚本只读指定的UTF-8文件，不写回CSV、不发起网络请求、不自动打开回答或来源链接。检查结果输出到终端，包含行号、字段名和错误代码，不回显整段问句、回答或单元格内容。

脚本识别的错误包括：18列表头或列数不匹配、重复记录编号、缺少必要字段、日期缺少时区、完成记录缺少回答或文件引用，以及“实际推荐是，但提及目标否”的冲突。带引号的逗号、双引号和多行回答可以正常解析。

警告包括：缺少账号或记忆条件、推荐但没记来源、遗漏来源支持与入口核对，以及可能被表格软件解释为公式的单元格开头。公式警告只提示人工检查，不执行公式，也不会改写原始回答；在表格软件中打开不可信内容前按文本方式导入。

输出示意结构如下，只展示字段含义，没有填入真实成绩：

{
  "format": "brand-evidence-18-column-v1",
  "dataRows": 0,
  "completedRows": 0,
  "errors": [],
  "warnings": [{"code": "NO_DATA_ROWS_BLANK_TEMPLATE_IS_NOT_A_TEST"}],
  "checksAreNotTruthVerification": true
}

这是空白模板的检查结果：没有数据，不代表完成了测试。退出码0只表示脚本没有发现格式错误，警告仍要查看；退出码1表示格式错误，2表示用法或读取失败。脚本最多读取10 MiB，这是辅助脚本自身的限制，与记录器的容量限制不同。

原始时间未知、平台用了不同状态名等情况，不应为了通过检查而编数据。保留原始文件，核对后在工作副本修正；无法修正的单列说明。

第四步：什么情况下适合用拾玖搜证台？

几条记录可以继续用表格。想在浏览器中集中手动保存完整回答、来源与人工复核标记时，可用拾玖搜证台在线记录器，或先用可填写工作单。

拾玖搜证台当前1.0.1免费，在浏览器本地保存人工记录，支持JSON、CSV、Markdown导出。换浏览器前先导出JSON备份；本文的18列CSV不能直接当作JSON导入。存储、容量和版本列的具体限制见使用帮助。本文的CSV检查脚本是单独辅助材料，没有集成到记录器，也没有改变记录器版本。

如果要每天自动采样、后台监控或多人实时共同编辑，应按这些需求另外选工具。拾玖搜证台不提供这些功能；它也不会自动登录、提问、截图或核验事实。火山方舟等模型API的回答不能直接当成豆包消费者端回答的验证结果。

复测时比较什么？

按同一道原题和同一条件跨时间复测，分别记录是否提及、是否实际推荐、事实和链接是否准确。网页更新、教程发布、脚本检查通过，都不等于AI已经收录或开始推荐。不要把换了问法的两次回答，当成修改前后效果对照。

这套工作流参考方鑫开源GEO医生的提问、诊断、按缺口补内容与原题复查流程。官方设置、平台规则和实际界面优先；遇到验证由本人完成，不绕过访问条件。
