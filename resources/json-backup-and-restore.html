豆包测试记录怎样备份、换浏览器恢复？

拾玖搜证台手动保存你粘贴的回答和当次来源。记录存在当前浏览器的localStorage，不会随账号自动出现在另一台电脑。

打开记录器 下载离线留证材料包

正常迁移：先留文件，再检查目标记录

  1. 在原记录器把批次筛选设为“全部批次”，点击“导出 JSON”。若只导出某个筛选范围，备份不会包含其他批次。
  2. 保留下载的JSON。CSV适合表格分析，Markdown是固定分组摘要和逐条记录，都不能代替可回导JSON。
  3. 在目标浏览器打开记录器，先备份目标原有记录，再选“导入 JSON”。核对预览中的新增数量和重复数量，再点击“确认合并”。同id记录跳过，不覆盖原记录。
  4. 核对问句、完整回答和来源，刷新页面后再核对数量。确认成功以前，保留原浏览器中的数据和独立JSON文件。截图文件仍须另存。

出现容量提示，先保留原文

记录器1.0.1：当前全部记录最多2000条，保存后的完整JSON不超过3,000,000个UTF-8字节；导入文件和合并结果也受同一总大小限制。浏览器配额可能更早触发。旧版已存在的超限历史可读取、导出并分批备份，不会自动改写；每份可独立导入，总量超限时不能重新合并到一个记录器。

如果是旧版已经保存的超限历史，1.0.1会提示“已读取旧版超限记录”，且不自动重写。点击“分批备份 JSON”，逐份点击下载按钮，每份保存在自己的文件夹。总量超过上限时，请分别在独立浏览器环境管理不同批次，不能把这些分片全部重新合并到同一个记录器。

如果提示历史格式异常，则先用“导出 JSON”备份原始存储，保留文件，不清理原数据；格式损坏的数据不会自动修复。浏览器配额、隐私模式和离线文件的存储行为也可能影响保存。

1.0.1这次实际修了什么？

  • 新保存、上传和合并总量都按UTF-8字节检查，避免中文文件按字符数通过却按字节数失败。
  • 超限保存拒绝写入，保留原记录及尚未保存的输入。
  • 旧版本地超限历史可读取并分批备份；无效文件不会沿用上一次导入预览。

验证使用合成记录：旧版超限历史读取、分批按钮实际下载、原生文件上传、确认合并、刷新恢复和离线打开均通过。没有使用客户数据，这些软件检查也不构成豆包搜索或推荐成功案例。

功能边界

没有自动提问、模型API、截图附件、云同步或自动事实判断。原有JSON格式仍为schemaVersion=1。CSV中的题集和事实卡列仍固定为q1/f1，需要按实际实验另留版本底稿。1.0旧发行版保留作历史版本，新版本请从当前官网入口下载。
